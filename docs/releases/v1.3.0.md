# v1.3.0 - Clearer and Safer Operator Workflows

`v1.3.0` improves the operator workflows for orders and Gateway deliveries,
with clearer state, safer retry handling, stronger access-token behavior and
responsive views. No HTTP or event schemas changed.

## Highlights

- **A coherent orders workflow:** complete-list and indexed-search scope are
  explicit; filters, pagination, URL state and return navigation stay aligned.
  Search diagnostics are secondary to the list, and refreshing an order detail
  is explicit.
- **Safer controlled delivery retries:** eligibility follows the Gateway's
  actual rules. Pending commands and idempotency keys survive dialog closure,
  navigation and uncertain responses; acceptance remains visible as delivery
  state advances. Error details and recovery guidance are clearer.
- **More useful order and delivery details:** order identity and operational
  status have clearer hierarchy, timeline timestamps retain database
  precision, delivery attempts are easier to inspect, and known Core orders are
  linked from deliveries.
- **Responsive operator views:** orders and deliveries use compact mobile cards;
  navigation, the architecture map and Flow Explorer adapt to narrow screens.
  Selected map details remain near the selected component.
- **Accessibility improvements:** token and retry dialogs support keyboard
  interaction, informational text meets the tested contrast threshold in both
  themes, and forced-colors behavior is covered by browser tests.
- **Stronger authentication consistency:** operator JWT claims are validated
  consistently by Core and Gateway, Core reads receive the configured bearer
  token, expired credentials can be replaced, and OIDC logs redact token data.

## Operational Boundary

This release does not add OIDC login or an identity provider, order-to-delivery
reverse lookup, Core processing-attempt replay, or new search capabilities.
Existing backend eligibility and authorization remain authoritative.
