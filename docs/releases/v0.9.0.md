# v0.9.0 - Observable Search Projection Progress

`v0.9.0` makes the OpenSearch order projection's successful progress visible
and durable. PostgreSQL remains authoritative; the projection is still an
eventually consistent read model.

## Highlights

- PostgreSQL persists one monotonic search-projection watermark containing the
  source event time and the time at which its projection completed.
- The Kafka consumer advances that watermark only after a successful
  OpenSearch write. Replayed or late events cannot move it backwards.
- The operator search-status API and the Operator Console expose the latest
  projected event, application time, and derived processing delay.
- Prometheus exports the processing delay and watermark age, and the
  version-controlled Grafana dashboard visualizes both measurements.

## Reliability And Security Boundary

The measurements describe the most recently advanced successful projection
watermark. They are not Kafka consumer lag: the watermark age naturally grows
while a healthy consumer waits for new source events.

The release does not add an operator command to start full reindexing. That
operation remains internal because a production command requires authenticated
identity, rationale, audit evidence, progress controls, and rollback
authorization.

## Upgrade Notes

Integration Core migration `V19__create_order_search_projection_progress.sql`
creates and seeds the durable watermark state. The migration does not alter
canonical orders or require an OpenSearch rebuild.

The Integration Core, Connector Gateway, and Operator Console package versions
advance from `0.9.0-SNAPSHOT` to `0.9.0` under the single-version policy.
