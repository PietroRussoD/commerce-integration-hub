# v0.8.0 - Rebuildable Order Search

`v0.8.0` adds an optional OpenSearch order projection to Commerce Integration
Hub. PostgreSQL remains authoritative; OpenSearch is a rebuildable read model
for operational inspection and never controls order-processing correctness.

## Highlights

- A dedicated `OrderReady.v2` consumer projects versioned order snapshots into
  an `orders-read` alias and atomically ignores equal or stale aggregate
  versions.
- The projection has bounded retries, dead-letter handling, outcome metrics,
  availability status, and a durable reconciliation job for READY orders.
- Safe full reindexing uses separate durable state and a fenced lease, creates
  a versioned candidate index, dual-writes concurrent projection updates,
  backfills bounded keyset pages, validates authoritative and candidate counts,
  and atomically cuts the read alias over only after validation succeeds.
- An integration test inserts an order behind the backfill cursor while the
  rebuild is running and verifies that the candidate retains it after cutover.
- The Operator Console displays projection availability, reconciliation,
  read-only reindex progress, and a projected-order search by item description,
  exact external order ID, or exact SKU. Search is disabled until the projection
  reports its read alias as available.
- Generated TypeScript API types, unit coverage, and local Playwright coverage
  keep the console aligned with the committed OpenAPI contract.

## Reliability And Security Boundary

The order projection is eventually consistent and isolated from successful
order processing. If OpenSearch is unavailable, canonical orders still complete
against PostgreSQL and the console disables projected search instead of
presenting an avoidable error.

Reindexing is intentionally an internal operation. A public operator command
needs authentication, identity, rationale, audit evidence, progress controls,
and rollback authorization; those controls remain outside this release.

## Upgrade Notes

Integration Core migrations create the OpenSearch reconciliation and reindex
state needed for durable leases, progress, and cutover. Enable the optional
Compose `search` profile and its explicit projection configuration to use the
read model locally. Existing authoritative order data remains in PostgreSQL.

All repository modules advance from `0.8.0-SNAPSHOT` to `0.8.0` under the
single-version policy.
