# v1.1.0 - Distributed Tracing Across Durable Workflows

`v1.1.0` adds opt-in distributed tracing across the Connector Gateway and
Integration Core. W3C trace context follows owned HTTP and Kafka boundaries and
is persisted separately when work resumes from PostgreSQL-backed queues.

## Highlights

- The Gateway traces signed webhook receipt, Core forwarding, delivery attempts,
  retries, and administrative replay. A replay starts a new trace linked to the
  latest prior attempt with complete trace context.
- The Core traces order ingestion, both transactional outbox dispatches, Kafka
  processing, and the OpenSearch projection consumer. Integration tests verify
  context restoration and propagation across these boundaries.
- The Operator Console links eligible delivery attempts to Jaeger when a local
  Jaeger URL is configured. No browser tracing SDK or custom trace viewer was
  added.
- The optional local OpenTelemetry Collector removes exception messages and
  stack traces before export. If redaction fails, the Collector drops the
  affected trace. Jaeger uses temporary local storage.

## Operational Boundary

Tracing remains disabled by default. Jaeger and the Collector are optional
local demonstration services; Jaeger history is lost when its container stops.
The Collector configuration is a local privacy control, not a production
security certification. Production deployments must review automatic span
attributes and configure equivalent redaction before exporting telemetry.

The release adds nullable database columns for trace context but does not
change HTTP or Kafka business contracts. Existing rows without trace context
remain valid. PostgreSQL remains authoritative for orders; OpenSearch remains a
rebuildable projection.
