# v1.4.0 - Operational Security and Payload Retention

`v1.4.0` makes release-image scans reproducible, adds an optional protected
operator profile to the Helm chart, and enforces bounded Gateway payload cleanup
for expired terminal deliveries. The demo profile remains open for local use;
cleanup remains disabled unless explicitly enabled.

## Highlights

- **Release-image security evidence:** the Container security workflow can scan
  both images by release tag or one image by immutable digest. It resolves and
  records the platform-specific digest, scanner and vulnerability-database
  metadata, report outcome and findings, and retains reports as workflow
  artifacts. Scheduled scans continue to inspect `latest`; their results are
  not release-image evidence.
- **Optional protected operator APIs:** Helm values can enable external OIDC
  JWT validation and role authorization for the Core and Gateway operator APIs.
  Local demo defaults remain disabled. The protected profile was exercised over
  real HTTP with synthetic issuer keys, including anonymous, invalid/expired,
  insufficient-role, operator-read and platform-admin replay cases. No identity
  provider or login flow is included.
- **Bounded Gateway payload retention:** opt-in cleanup clears raw and canonical
  payload columns only for expired terminal deliveries. Active deliveries keep
  both payloads beyond their expiry until they reach a terminal state. Delivery
  identity, deduplication hashes, attempts, audit history and terminal outcome
  remain available. Cleanup uses bounded batches, tolerates concurrent replicas,
  and waits for an in-flight database batch during graceful shutdown. The
  configured interval is not a guaranteed erasure deadline.

## Operational Boundary

This release does not add user login, password or refresh-token handling, user
or role management, or identity-provider deployment. External identity-provider
integration was not verified. Payload retention applies only to Gateway raw and
canonical payload columns; it does not erase Core orders, PostgreSQL WAL,
replicas or backups. Expired active deliveries remain retained until terminal.
Cleanup is disabled by default and has no universal 30-day maximum or guaranteed
erasure deadline. This release makes no production-readiness, compliance,
availability, throughput or latency claim.
