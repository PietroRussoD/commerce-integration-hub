# v0.4.0 - Operator Console and Controlled Simulation

`v0.4.0` adds a React and TypeScript operator console to the reliable order
processing platform. Operators can inspect order summaries and operational
details, while a deliberately constrained simulator demonstrates fresh,
equivalent, conflicting, and invalid canonical submissions against the real
Integration Core.

## Highlights

- Read-only operator APIs expose paginated summaries and details across source
  systems, including items, timeline entries, and processing attempts.
- The React console provides filtering, pagination, order navigation, loading,
  empty, and failure states through generated OpenAPI types and TanStack Query.
- The simulator submits canonical orders with a source API key kept only in
  page memory and makes replay and conflict behavior directly observable.
- English and Italian localization covers navigation, data formatting,
  operational content, feedback, and validation.
- Hostname-selected brand themes separate identity tokens from shared layout
  and behavior without introducing separate application builds.
- Shared components are developed and documented in Storybook.
- The console targets WCAG 2.2 Level AA without claiming formal conformance.
  Automated Axe checks, structured field errors, focus management, keyboard
  skip navigation, and narrow-viewport overflow checks support that target.
- Local Playwright tests cover list-to-detail navigation, simulator success,
  validation recovery, keyboard navigation, and mobile layout in Chromium.

## Verification

The final release rehearsal completed these independent gates:

- `./mvnw verify`: 131 unit tests and 129 integration tests passed;
- `pnpm check:api`: generated TypeScript API types matched the committed
  Integration Core OpenAPI contract;
- `pnpm check`: linting, three TypeScript configurations, 56 Vitest tests with
  enforced coverage, the production build, and the Storybook build passed;
- `pnpm test:e2e`: all four local Chromium browser scenarios passed;
- GitHub Actions run
  [`33204508914`](https://github.com/PietroRussoD/commerce-integration-hub/actions/runs/33204508914)
  passed the final snapshot commit through the Integration Core and
  operator-console jobs, including full-history secret scanning, coverage and
  SBOM artifacts, and final-image vulnerability scanning.

The Compose rehearsal used isolated PostgreSQL and Redpanda volumes. A
temporary source credential created a real order with `201 Created`; an
equivalent replay returned `200 OK`; conflicting content returned `409
Conflict`; and asynchronous processing moved the order to `READY` in one
attempt. The matching `OrderReceived` and `OrderReady` events were present on
their separate topics with a correlation ID. Health reported the database and
messaging channels as `UP`, Prometheus exposed HTTP and Kafka metrics, and
Redpanda Console returned `200 OK`.

A separate headless-browser smoke test exercised the live Vite-to-Quarkus flow
on desktop and mobile. It found no browser console errors, failed requests,
server errors, or global horizontal overflow at 390 px.

## Accessibility Boundary

Automated checks are evidence, not a WCAG conformance audit. Color contrast,
screen-reader behavior, zoom, forced-colors mode, and the complete manual-state
matrix remain in the documented audit checklist.

## Operational Boundary

The operator APIs are read-only and do not yet have user login or role-based
authorization. The simulator is intended for local development and portfolio
demonstration, not production operation. Provider-specific normalization,
audited recovery actions, OpenSearch projections, and distributed tracing
remain outside this release.

## Upgrade Notes

This release adds no Flyway migration beyond the `v0.3.0` data model. The
operator console is a separate static frontend and expects an Integration Core
that exposes the committed `v0.4.0` OpenAPI contract.
