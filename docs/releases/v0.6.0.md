# v0.6.0 - ERP Polling and Local Observability

`v0.6.0` adds a cursor-based `ERP_B` polling adapter to the Connector Gateway
and makes its durable runtime state visible through a version-controlled local
Prometheus and Grafana stack. The adapter converts provider pages into the same
canonical order boundary used by signed webhooks without coupling provider
contracts to the Integration Core.

## Highlights

- Strict provider-page parsing, semantic mapping, deterministic fingerprints,
  and typed classification distinguish forwardable deliveries, permanent
  mapping rejections, and equivalent replays.
- A bounded HTTP client applies bearer authentication, request timeouts,
  cancellation, manual redirect handling, streamed response limits, and typed
  retry classification.
- PostgreSQL stores polling checkpoints, page outcomes, and deliveries in one
  transaction. A failed page cannot advance its cursor or expose partial work.
- Short leases and UUID fencing tokens coordinate multiple polling replicas.
  Conditional acquisition, renewal, commit, and release reject stale owners.
- The non-overlapping scheduler runs immediately when explicitly enabled,
  processes a bounded number of pages, and shuts down cooperatively.
- Provider `401` and `403` responses move an active connector to
  `BLOCKED_CONFIGURATION` under the current fencing token. Disabled connectors
  and newer owners cannot be overwritten.
- Durable Prometheus gauges expose eligible backlog count and age, fixed
  connector-state counts, and the latest successful ERP_B checkpoint age.
  Process-local counters expose bounded worker and polling outcomes.
- A deterministic provider simulator exercises multi-page success, an
  unsupported-currency rejection, pagination, and authentication behavior.
- The optional Compose `observability` profile pins Prometheus and Grafana and
  provisions a read-only ten-panel operations dashboard from repository files.
- A self-cleaning release smoke test builds and verifies the complete topology
  in an isolated Compose project without reusing development volumes.

## Reliability Semantics

Polling delivery is at least once. A provider change ID and canonical payload
fingerprint make replay classification deterministic. A page transaction
persists every item outcome and its next cursor together, while the current
lease owner and fencing token protect checkpoint mutation. A crash before
commit leaves the previous cursor visible; a crash after commit may repeat the
request but cannot create a second logical delivery.

Operational gauges are read from one PostgreSQL snapshot per scrape and must
not be summed across Gateway replicas. Process-local counters may be summed by
Prometheus. Free-form errors, connector IDs, delivery IDs, worker IDs, URLs, and
cursors are deliberately excluded from metric labels.

## Security Boundary

The committed API token, webhook secret, database passwords, and Grafana
anonymous access are local-development settings. Prometheus and Grafana bind to
localhost in Compose. Production deployments must inject secrets through an
external secret-management boundary, terminate TLS, and restrict health and
metrics endpoints to trusted infrastructure.

Grafana provisioning is read-only and automatic plugin installation is
disabled. The local dashboard does not add operator authorization, production
alerting, distributed tracing, or a supported monitoring deployment.

## Operational Boundary

`MARKETPLACE_A` signed webhooks and `ERP_B` cursor polling are the only provider
adapters. Polling and delivery workers remain disabled by default and must be
enabled independently. The provider simulator, Prometheus, and Grafana are
development and portfolio tools rather than production service dependencies.

OpenSearch projection, the integration flow explorer, production alert rules,
Kubernetes deployment, and operator-controlled recovery actions remain outside
this release.

## Upgrade Notes

Connector Gateway migration `006` adds connector polling configuration,
checkpoint leases, cursor state, and durable item outcomes. Existing
Integration Core and operator-console schemas are unchanged.

Polling deployments must configure `ERP_B_POLLING_ENABLED`, a worker ID, the
provider base URL and API token. Interval, lease, page-limit, connector-ID,
request-timeout, and response-size settings have validated bounded defaults.
The Connector Gateway package version for this milestone is `0.6.0`.
