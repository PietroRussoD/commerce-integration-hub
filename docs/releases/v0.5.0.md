# v0.5.0 - Durable Provider Gateway and Forwarding

`v0.5.0` adds a Node.js and TypeScript Connector Gateway between external
provider contracts and the canonical Integration Core API. The first
`MARKETPLACE_A` adapter authenticates and validates signed webhooks, commits
their canonical form durably, and forwards them through a bounded recoverable
worker without exposing provider-specific behavior to the core domain.

## Highlights

- Raw request bytes are authenticated with timestamp-bound HMAC-SHA256,
  constant-time comparison, bounded freshness, and current/previous key
  rotation before provider payload parsing.
- Strict provider validation and deterministic mapping produce a versioned
  canonical order plus a SHA-256 raw-payload fingerprint.
- A dedicated PostgreSQL delivery ledger classifies first receipt, equivalent
  replay, and conflicting bytes atomically. Webhooks receive `202` only after
  durable commit.
- Kysely migrations, short `SKIP LOCKED` leases, UUID fencing tokens, and an
  attempt ledger coordinate concurrent workers without holding database
  transactions across HTTP calls.
- The Integration Core client applies bounded timeouts, disables automatic
  redirects, validates success responses, honors capped `Retry-After`, and
  maps failures to persisted retryable, permanent, exhausted, or blocked
  outcomes.
- An opt-in non-overlapping scheduler recovers expired claims before each
  bounded batch and stops cleanly on process termination.
- Separate liveness and PostgreSQL readiness endpoints preserve webhook receipt
  during Core outages. Prometheus exposes Node.js and fixed-cardinality worker
  metrics without delivery IDs, worker IDs, URLs, or error text as labels.
- A multi-stage Node.js 24 build produces a non-root distroless Debian 13
  runtime with pinned base-image digests. GitHub Actions publishes `latest`,
  scheduled Trivy jobs scan both service images, and release tags promote
  verified component images without rebuilding them.

## Security Boundary

The committed Compose credentials are local-development values. Production
deployments must supply webhook keys and Integration Core source credentials
through a secret-management boundary, restrict `/metrics` to monitoring
networks, and terminate TLS before the service. Integration Core authentication
failures block the connector non-destructively instead of retrying invalid
credentials indefinitely.

The runtime image intentionally contains no shell, npm, corepack, or operating
system package manager. This reduces attack surface but also means operational
debugging must use logs, metrics, health endpoints, database evidence, or an
ephemeral diagnostic container rather than modifying the running container.

## Operational Boundary

Only the signed `MARKETPLACE_A` webhook adapter is implemented. Cursor-based
polling, additional providers, Kubernetes deployment, distributed tracing, and
operator-controlled delivery replay remain outside this release. The worker is
disabled by default in Compose until a valid Integration Core source credential
is supplied.

## Upgrade Notes

The Connector Gateway owns a separate PostgreSQL database and applies Kysely
migrations `001` through `005` using a one-shot deployment job. Existing
Integration Core and operator-console data models are unchanged. Deployments
must configure `DATABASE_URL` and the current webhook key; forwarding also
requires `DELIVERY_WORKER_ENABLED`, a worker ID, the Core base URL, and a source
API key. The Gateway package and container version for this milestone is
`0.5.0`.
