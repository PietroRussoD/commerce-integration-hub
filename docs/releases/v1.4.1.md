# v1.4.1 - Runtime Security Updates

**Release preparation:** the tag, promoted images and GitHub Release have not
yet been created. The checks below identify the evidence available so far;
they do not certify a future release image.

## Changes

- Override the Core's transitive Guava and snappy-java dependencies and update
  the affected operating-system packages when building its runtime image.
- Update the Gateway's distroless base and temporarily copy the fixed Debian 13
  zlib library and its package metadata into the non-root runtime. The pinned
  package must remain available in Debian's configured repositories. Remove
  the temporary stage when the distroless base includes the fix.
- Update the console's Storybook and zod, and update vulnerable transitive
  dependencies and test tooling in the JavaScript modules. Targeted pnpm
  overrides keep compatible patched versions until upstream constraints and
  lockfiles can be updated without them.

## Evidence and remaining release checks

- On 8 November 2026, the local candidate passed Core `./mvnw verify`, console
  `pnpm check:api` and `pnpm check`, Gateway `pnpm check` and
  `pnpm test:integration`, simulator `pnpm check`, the repository version
  check, Helm lint and the Prometheus alert-rule tests. After the JavaScript
  dependency updates, the affected module checks passed again and an isolated
  Compose smoke test confirmed Gateway tracing reaches Jaeger.
- CI passed for the Core security change at `9af0648` and the Gateway change at
  `bec13ad`. The Gateway tests include 708 unit and 138 integration tests.
- Trivy 0.74.0 scans of the CI-produced Core and Gateway image digests passed
  with no HIGH or CRITICAL OS or library findings, including unfixed findings:
  [Core scan](https://github.com/PietroRussoD/commerce-integration-hub/actions/runs/42419908928)
  and [Gateway scan](https://github.com/PietroRussoD/commerce-integration-hub/actions/runs/42465332128).
  These scans do not certify images promoted under a release tag.
- The release candidate still needs a successful CI run on its exact commit.
  After the verified commit is tagged and images are
  promoted, scan both tag-resolved immutable digests and record the reports
  before creating the GitHub Release.

On 8 November, `pnpm audit` reported no HIGH or CRITICAL findings in the three
JavaScript modules after the dependency updates. It still reported MODERATE
findings in `glob` and `minimatch`. Production-only audits returned no findings
for the console or simulator, and one MODERATE `minimatch` finding through
`@fastify/otel` for the Gateway. In the current integration, tracing is disabled
by default; when enabled, this dependency matches application route definitions
against an optional operator-controlled `OTEL_FASTIFY_IGNORE_PATHS` pattern.
This limits the observed input path but does not prove the vulnerability is
unexploitable. The patched `minimatch` version is a new major; replacing it
outside the upstream dependency range or migrating OpenTelemetry requires a
separate compatibility review. Development-only `glob` and `minimatch`
findings also remain; audit results can change as advisories are updated.

The `v1.4.0` release images were rescanned on 7 November 2026 and had HIGH
findings ([scan](https://github.com/PietroRussoD/commerce-integration-hub/actions/runs/42419947661)).
Historical results apply to the images and vulnerability database scanned at
that time; they are not a guarantee about later images or databases.
